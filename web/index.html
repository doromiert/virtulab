AUTOMATYCZNE PRZYGOTOWANIE

Tryb konfiguracji

System pobierze wieloedycyjny obraz Windows 11 x64 bezpośrednio z serwerów Microsoft, przygotuje RouterOS i uruchomi jedną maszynę szablonową z dostępem NAT.

Opcje zaawansowane
Źródło automatycznego pobierania

Lokalny obraz omija pobieranie Microsoft. Upewnij się, że pochodzi z zaufanego źródła i samodzielnie zweryfikuj jego sumę SHA-256.

Gotowy do konfiguracji

PIERWSZE URUCHOMIENIE

Konfiguracja maszyn wirtualnych

Wybierz sposób uruchomienia. Obraz ISO możesz dostarczyć ręcznie albo pobrać bezpośrednio z Microsoft przyciskiem „Tryb konfiguracji” na górnym pasku.

  1. 01

    Przygotuj hosta

    Włącz w UEFI wirtualizację sprzętową. Host Linux musi mieć KVM, libvirt, OVMF i emulator TPM. Na NixOS dodaj poniższą konfigurację, przebuduj system, a następnie wyloguj się i zaloguj ponownie.

    { virtualisation.libvirtd = { enable = true; qemu.swtpm.enable = true; }; programs.virt-manager.enable = true; users.users.TWOJ_UZYTKOWNIK.extraGroups = [ "libvirtd" ]; }

    Dokumentacja libvirt w NixOSDokumentacja KVM

  2. 02

    Pobierz obraz Windows 11

    Pobierz oficjalny obraz x64, nazwij go win11.iso i przechowuj poza katalogiem projektu, aby Nix nie kopiował wielogigabajtowego ISO do swojego magazynu.

    Oficjalny obraz Windows 11Warunki licencyjne Microsoft

  3. 03

    Przygotuj i uruchom laboratorium

    Uruchom polecenia w katalogu projektu, podając bezwzględną ścieżkę do ISO. Nix pobierze i sprawdzi przypięte wersje CHR, WinBox i Lucide, utworzy dyski oraz zdefiniuje trzy maszyny w libvirt.

    MIKROTIK_WIN11_ISO=/pełna/ścieżka/win11.iso \ MIKROTIK_VM_STORAGE=/ścieżka/na/szybkim/dysku \ nix run .#setup nix run .#ui

  1. 01

    Zainstaluj zależności hosta

    Włącz w UEFI wirtualizację sprzętową, a następnie użyj polecenia właściwego dla dystrybucji.

    Debian / Ubuntu

    sudo apt update sudo apt install qemu-kvm qemu-utils libvirt-daemon-system libvirt-clients virt-viewer swtpm ovmf xorriso python3 curl sudo usermod -aG libvirt,kvm "$USER"

    Fedora

    sudo dnf install @virtualization virt-viewer swtpm edk2-ovmf xorriso python3 curl sudo usermod -aG libvirt,kvm "$USER"

    openSUSE Leap / Tumbleweed

    sudo zypper install -t pattern kvm_server kvm_tools sudo zypper install libvirt-client virt-viewer swtpm swtpm-tools ovmf xorriso python3 curl sudo usermod -aG libvirt,kvm "$USER"

    Oficjalna dokumentacja libvirt openSUSE

    Arch Linux

    sudo pacman -S qemu-full libvirt virt-viewer swtpm edk2-ovmf xorriso dnsmasq python curl sudo usermod -aG libvirt,kvm "$USER"
    sudo systemctl enable --now libvirtd virsh -c qemu:///system list --all

    Po dodaniu grup wyloguj się i zaloguj ponownie. Polecenie virsh musi działać bez sudo.

KROKI WSPÓLNE

  1. 04

    Uruchom RouterOS CHR

    RouterOS nie wymaga instalacji z ISO. CHR jest gotowym dyskiem systemowym pobranym podczas przygotowania laboratorium. Przy routerze naciśnij ikonę uruchomienia , a następnie ikonę konsoli . Zaloguj się jako admin; świeży obraz CHR nie ma hasła. Ustaw własne hasło natychmiast po pierwszym logowaniu.

    /user set [find name=admin] password="TU_WPISZ_UNIKALNE_HASLO" /system identity set name=R1-INF02 /interface ethernet set [find default-name=ether6] name=sfp1

    Szósty interfejs CHR jest pokazany w UI jako port SFP, dlatego polecenie zmienia jego nazwę z ether6 na sfp1. Po ustawieniu hasła możesz zamknąć konsolę.

    Aby użyć WinBox, uruchom router i klienta podłączonego do jednego segmentu. W WinBox otwórz kartę Neighbors, wybierz router po adresie MAC i zaloguj się jako admin z ustawionym hasłem.

    Pierwsza konfiguracja RouterOSDokumentacja WinBoxLicencje CHR

    Darmowa licencja CHR udostępnia funkcje RouterOS, ale ogranicza wysyłanie do 1 Mb/s na interfejs. Do ćwiczeń konfiguracyjnych wystarcza; testy wydajności wymagają licencji próbnej lub P1.

  2. 05

    Zainstaluj jeden szablon Windows

    Setup automatycznie otworzy jedną maszynę szablonową z dostępem NAT i zatrzyma się w terminalu. Zainstaluj Windows 11, otwórz płytę WINTOOLS, uruchom jako administrator Install-WinBox.cmd, a następnie doinstaluj dowolne potrzebne programy. Instalator WINTOOLS rejestruje też jednorazowe automatyczne nazwanie klonów jako CLIENT01 i CLIENT02.

  3. 06

    Zapisz wspólny punkt przywracania

    Wyłącz szablon normalnie z menu Start. Opcjonalnie wcześniej uruchom Sysprep.exe /generalize /oobe /shutdown, jeśli klienci mają otrzymać różne tożsamości Windows. Gdy VM będzie całkowicie wyłączona, wróć do terminala setupu i naciśnij Enter.

    Skrypt zabezpieczy szablon przed zapisem i utworzy z niego dwa małe dyski robocze. Ikona obu klientów będzie odtwarzać właśnie ten wspólny stan.

    Wyłącz szyfrowanie urządzenia albo zachowaj klucze odzyskiwania TPM przed zapisaniem szablonu.

  4. 07

    Podłącz sieć

    Wyłącz wszystkie VM przed użyciem „Zastosuj okablowanie”. Gniazdo ścienne WAN udostępnia NAT i DHCP w sieci 172.31.255.0/24. Po podłączeniu routera dodaj klienta DHCP na odpowiednim interfejsie RouterOS.

    /ip dhcp-client add interface=ether1 disabled=no

    Sprawdź adres i trasę domyślną poleceniami /ip dhcp-client print detail oraz /ip route print. Przywrócenie routera w UI usuwa wszystkie zmiany i odtwarza oficjalny, czysty obraz CHR.
